# 固定路线推进、天然机油与模式排行榜设计

状态：实现完成（按实施计划交付）
日期：2026-09-23
阶段：#6 尚未通过；用户已明确授权本方案作为 #6 前例外并确认设计。实现按配套实施计划执行。

## 背景

当前主线已有 1–4 路动态生成机制、AI / 人类两种玩法和服务端成绩记录。玩家可以在 Settings 中选择路数；人类模式成绩目前不入榜；服务端每局记录未保存玩法模式。人类模式目前无需输入昵称且加载后立即开局；新增人类排行榜需要复用昵称门槛，并在昵称确认后开始并记录人类对局。此变更要把路线数改为按波次推进，增加能被玩家点击的攻击速度道具，并扩展排行榜以区分 AI 与人类成绩。

用户确认天然机油在 AI 与人类挑战中都可使用。AI 模式仍由 AI 部署炮塔；人类可额外手动触发天然机油。

## 目标与明确规则

### 1. 波次决定路线数

路线数按即将开始的波次确定：

| 波次 | 路线数 |
| --- | ---: |
| 1–50 | 1 |
| 51–100 | 2 |
| 101–150 | 3 |
| 151 及以后 | 4 |

波次边界统一采用「更新路线 → 让 AI 观察并规划 → 开始出兵」的顺序。第 1 波开始时只有 1 路。移除 Settings 里的路数选择和 spawners 查询参数对路数的控制。

所有未来出生点从第 1 波起都必须可用：炮塔放置与随机地形生成须保留每个未来出生点至基地的可达路径，不能让未来的路线被既有炮塔封死。启用路线后沿用现有路径缓存失效和敌人重算路径机制。若某个新增出生点无法启用，不得悄悄进入较少路线数的错误状态；路线约束应在前序建造校验中防止该状态。

### 2. 天然机油

- 图标放在炮塔选择区下方，使用简单色块占位，并提供名称、价格和可用状态。
- AI / 人类两种模式都能点击使用。
- 每次成功激活花费 2000 cash；现金不足时不扣款、不触发效果，并显示失败状态。
- 效果作用于所有己方、具有正攻击间隔的炮塔：攻击间隔按 1 / 1.5 缩短，即攻击速度提高 50%；伤害不变。
- 效果持续 5 秒；结束后才开始 10 秒冷却。激活或冷却期间按钮不可再次触发，不可叠加。
- 持续时间和冷却使用游戏模拟时间：暂停或 AI 的 PLANNING 阶段会冻结计时，x2/x4/x8 速度会相应加快计时。
- 仅在 RUNNING 状态可使用。该规则避免在尚未开局、暂停或规划中消耗时长。
- 计时逻辑与 DOM 解耦，炮塔更新在引擎侧读取统一的攻击速度倍率；界面只负责状态显示与调用激活入口。

### 3. AI、人类与总排行榜

- AI 榜继续按每个昵称的 AI 对局最高波次排名。
- 人类榜按每个昵称的人类对局最高波次取前十。
- 总榜从 AI 与人类各自每个昵称的最佳记录中合并，按波次降序、服务端首次到达时间升序排列后取前十。
- 同一昵称可以在总榜出现两次：分别显示 AI 和人类标志。昵称按大小写不敏感归并，但模式不同的成绩不互相覆盖。
- 榜单按钮从当前游戏模式对应的榜单开始：当前 AI 模式为 AI → 人类 → 总榜 → AI；当前人类模式为人类 → AI → 总榜 → 人类。切换运行模式后，页面重载并从新运行模式对应的榜单开始。
- AI 成绩行保留现有 Prompt 历史入口；人类成绩不显示 Prompt 历史入口。
- AI 榜的既有排序和前十保持不变。每种榜单仍显示当前昵称名次；总榜显示当前昵称在两种模式中的较佳总榜名次与模式标记。
- 离线本地成绩继续明确标记为本机数据。旧版本地记录没有模式字段时按 AI 成绩读取。

## 实现方案

### 方案比较

1. **扩展现有边界（推荐）**：复用 WavesManager 波次边界、Map 路线切换、引擎更新循环、LeaderboardClient / RunSync 与服务端排行榜 Store。增加纯函数路线计划、天然机油状态对象和 mode-aware 的服务端记录 / 查询。优点是复用现有执行时序与成绩真值边界，改动保持聚焦。
2. **另建完整的路线、道具与榜单子系统**：为三项需求各建独立调度、模拟和存储层。组件隔离度略高，但会与现有波次、炮塔和排行榜逻辑重复，增加同步与测试负担。
3. **只在前端区分榜单**：本地保存人类 / AI 标记，不扩展服务端。实现较短，但无法提供跨设备共享的人类榜和总榜，服务端读取仍无法按模式权威归类，违反现有排行榜数据边界。

采用方案 1。

### 路线模块

新增一个无 DOM 的路线计划函数，并由 WavesManager 在每个波次开始前执行。移除运行时手动选择入口及旧查询参数读取。Map 保留所有四个出生点的可达性约束；路线增加仍触发现有 map-added 路径刷新事件。将 AI 状态快照中的实际路线继续作为事实来源。

### 天然机油模块

新增依赖无 DOM 的道具控制器，接收现金端口、模拟步进和状态变更回调。成功激活时先检查并扣款，再进入 active；状态机为 ready → active(5s) → cooldown(10s) → ready。按钮不可用或余额不足时返回结构化状态，不允许静默失败。所有攻击间隔由公共倍率读取，避免逐炮塔保存 / 恢复临时数值而造成升级或新建炮塔状态错乱。

### 按模式记录排行榜

- 为服务端 runs 增加 mode 字段，允许值为 ai / human。迁移时历史 run 默认 ai，从而保持现有 AI 排名。
- 创建 run 时由客户端提交模式；服务端验证枚举并在 run 创建时写入。后续波次记录只按已创建 run 的 mode 归类，不能由单次波次上报改变模式。
- /api/leaderboard 增加榜单模式参数：省略时默认 ai，并支持 human 与 total。total 查询按 (lowercase username, mode) 聚合最佳成绩，再统一排序与截取前十。
- 服务端榜单响应的每行附带模式；当前用户名次按当前榜单语义返回。AI / 人类视图返回各自排名；总榜视图返回该昵称在 AI / 人类记录中排名靠前的一项。
- 人类模式复用现有昵称门槛并在确认后开始自动对局；AI 模式继续在玩家开始策略局时创建 run。两种模式的波次都通过现有服务端 run / wave-event 证据路径同步。recordWave 仍以 run ID 和服务端持有的 mode 为准；AI Prompt 历史查询仍只选择 AI run。
- 本地 fallback 记录按 (username, mode) 分组。旧记录缺少 mode 时按 AI 处理，避免旧 AI 成绩丢失。

实现时更新 docs/PRODUCT_CONCEPT.md：记录固定路线计划、天然机油规则、人类模式可上榜、总榜合并语义与模式标记；移除或改写「人类模式成绩不计入排行榜」及已由用户决定的排行榜模式未决项。同步更新 AGENTS.md 中「排行榜后端是唯一例外」的阶段门槛例外，明确新增例外只覆盖本设计中的固定路线、天然机油和模式排行榜。不得更改其余阶段限制。

不引入运行时依赖，不将客户端上报分数说成服务端模拟证明。服务端仍校验 run 所属昵称、模式固定性、波次递增、范围和有效期；浏览器上报波次的已知限制仍需保留。

## 风险与边界

天然机油允许人类在 AI 模式直接触发战场增益，是本次明确批准的 AI 模式直接干预例外；它不开放人类放塔、升级或其他直接操作。共享排行榜目前仍由浏览器上报波次，服务端不重演游戏；mode 固定到 run 只能防止一局中途切换标签，不能证明客户端实际按该模式运行。四路线计划收紧可建造格范围，是维持后续路线必然启用的必要条件，需用现有可建造格与 A* 测试验证其影响。
