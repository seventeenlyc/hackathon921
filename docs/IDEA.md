# Hackathon 921 — 创意文档

## 工作概念

**一款由人类与 AI 共同游玩的 roguelike 塔防游戏。**

> **玩家不操控防御塔。玩家编写策略 Prompt；AI 走上战场，按 Prompt 行事。**

本次黑客松的目标是做出一个**真正可玩的版本**，而不是一个庞大的平台。

---

## 1. 核心创意

传统塔防要求玩家直接放置防御塔、升级、出售，并应对敌人。

本作改变了操控界面。

人类**不**直接操作战场，而是编写自然语言的策略指令，例如：

- 始终保持至少 25% 的金币作为储备。
- 在增加伤害之前，优先减速快速敌人。
- 在隘口附近建造范围伤害塔。
- 如果敌人逼近基地，立即行动，而不是花时间做长时间思考。

一旦一局开始，AI 会观察游戏状态、做出决策，并用游戏工具执行行动。

接着玩家观看自己 Prompt 所造成的结果。

核心循环是：

**写 Prompt → AI 作战 → AI 成功/失败 → 理解发生了什么 → 重写 Prompt → 再试一次**

或者用 roguelike 的语言来说：

**战斗 → 死亡 → 学习 → 重写 Prompt → 再战**

---

## 2. 核心幻想

玩家不是战场操作员。

玩家是 **AI 玩家的战略家 / 训练师 / 架构师**。

这种幻想是：

> **“我训练了这个 AI。现在我得让它独自上战场。”**

这与普通塔防制造出不同类型的张力。战斗一旦开始，玩家无法通过微操来拯救 AI。玩家指令的质量必须经得起游戏世界的检验。

---

## 3. 为什么这很有趣

### 3.1 首先它应该是一款真正的游戏

项目不应该让人感觉像是一个套了游戏 UI 的 Agent 基准测试。

玩家应该体验到：

- 试验；
- 期待；
- 失败；
- 迭代；
- 构筑优化；
- 当 AI 对指令的理解与预期不同时的惊喜；
- 当小小的 Prompt 改动带来可见行为改善时的满足感。

关键的游戏技巧不是点得更快。

而是**把策略传达给一个智能体**。

### 3.2 Prompt 成为一种游戏机制

对许多人来说，Prompt Engineering 很抽象。他们往聊天框里输入文字，又收到一堆文字。

本作把 Prompt 的效果变得具体、可观察，并呈现在一个模拟世界中：

**人类语言 → AI 决策 → 游戏行动 → 世界结果**

举例：

第 1 局：

> 守住基地。

AI 激进地花钱，在第 5 波阵亡。

玩家加上：

> 至少保留 25% 的金币以备不时之需。

第 2 局撑到了第 7 波。

玩家立刻明白，Prompt 不只是一个问题。它可以定义行为策略、约束、优先级、战略与例外情况。

游戏应该通过游玩来教会这一点，而不是通过一个“Prompt Engineering 101”教程。

### 3.3 通过失败学习 Prompt 技巧

玩家可以自然地发现这些概念：

- 目标；
- 约束；
- 优先级；
- 战略；
- 例外；
- 歧义；
- 冲突指令；
- 反馈；
- 记忆；
- 过度思考；
- 延迟与决策质量。

因此，一个好的失败界面不应只说：

> 游戏结束 — 第 8 波

它应该帮助回答：

> **你的 AI 为什么会死？**

然后邀请玩家修改 Prompt，并立刻验证这个假设。

### 3.4 游戏之下的 Agent 测试平台

同一套环境可以测量真实的 Agent 系统属性：

- 决策延迟；
- 首次行动时间；
- 纠正行动时间；
- token 用量；
- 成本；
- 决策质量；
- 工具使用正确性；
- 资源分配；
- 适应能力；
- 记忆使用；
- 鲁棒性；
- 通信开销；
- 多 Agent 协作。

重要的指标不只是模型原始的 TPS。

一个更有用的概念是**实时压力下的有效能动性**：

> 在世界发生变化之前，Agent 能多快地产出一个有用的行动？

一个模型可能推理正确，却因为决策来得太晚而落败。

游戏把延迟变成一种可见的游戏约束：

> **想得快，否则就死。**

---

## 4. 为什么是塔防

塔防很有用，因为它天然提供了：

- 持续决策，而非一次性的问答；
- 实时压力；
- 资源约束；
- 长期规划；
- 客观结果；
- 逐步升级的难度；
- 清晰的视觉状态；
- 可复现的随机种子；
- 简单的工具动作；
- 一眼就能理解的胜负条件。

旁观者不需要理解 LLM 评测。

他们只需要理解：

> **这个 AI 让基地活了多久？**

---

## 5. 人类与 AI 的角色

### 人类

人类编写并迭代策略 Prompt。

后续版本可能允许人类：

- 选择 Prompt 天赋；
- 挑选可继承的经验教训；
- 配置 Agent 角色；
- 选择模型；
- 设计一个 swarm（智能体集群）；
- 对成功的 Prompt 构筑进行分叉或变异。

### AI

AI：

1. 观察压缩后的游戏状态；
2. 解读玩家的 Prompt；
3. 决定要做什么；
4. 调用被允许的游戏工具；
5. 观察结果；
6. 循环往复，直到胜利或死亡。

AI 应该做**战略决策**，而不是控制每一帧动画。

确定性的游戏引擎负责：

- 移动；
- 索敌；
- 伤害；
- 弹道；
- 寻路；
- 防御塔攻击循环；
- 逐帧模拟。

---

## 6. MVP

黑客松 MVP 应该只证明一件事：

> **改变 Prompt 会导致明显不同的 AI 策略，以及明显不同的游戏结果。**

### 一张地图

一条简单的固定路线，带少量建造位置。

### 三种敌人类型

- 普通
- 快速
- 坦克

### 三种防御塔类型

- 单体伤害
- 范围伤害
- 减速 / 群体控制

### 最小 Agent 工具集

概念上：

```
inspect_game()
build_tower(type, position)
upgrade_tower(id)
sell_tower(id)
```

### 玩家界面

一个主要输入：

**你的策略 PROMPT**

然后：

**开始本局（START RUN）**

本局开始后，人类不再直接控制战场。

### Agent 决策循环

游戏本身以浏览器游戏的正常速度运行。

LLM 只被周期性地调用，或在有意义的事件发生时调用，例如：

- 波次开始；
- 敌人组成变化；
- 积累了足够金币；
- 基地受到威胁；
- 重大战术条件变化。

LLM 收到压缩后的游戏状态，并返回一个结构化动作。

这避免了试图把 LLM 当作 30/60 FPS 控制器来使用。

---

## 7. MVP 的神奇时刻

最重要的实验应该在视觉打磨之前完成。

用完全相同的 map 和随机种子，跑两个 Prompt。

### Prompt A

> 激进花钱。立即最大化伤害。

### Prompt B

> 保留 30% 的金币作为储备。在继续增加伤害之前，优先减速快速敌人。

如果旁观者能肉眼看出两个 AI 行为不同，核心创意就成立了。

期望的反应是：

> **“我改了一句话，它真的改变了 AI 的打法。”**

这就是本项目首要的神奇时刻。

---

## 8. Roguelike 循环

第一个版本不需要复杂的道具或遗物系统。

一个最小的 roguelike 循环就够了：

1. 玩家写 Prompt。
2. AI 作战。
3. AI 阵亡。
4. 游戏展示简短的事后复盘。
5. 玩家修改 Prompt。
6. 重玩相同或相近的挑战。
7. 玩家尝试存活更久。

之后，Prompt 指令本身可以成为 roguelike 天赋。

示例：

### 应急资金（EMERGENCY FUND）

> 保留 25% 的可用金币作为储备。

### 威胁优先（THREAT FIRST）

> 按“到基地的时间”而非 HP 来对敌人排优先级。

### 反射（REFLEX）

> 如果威胁 ETA 低于 3 秒，立即行动，而不是进行长时间的战略思考。

### 反思（REFLECT）

> 每一波结束后，找出最大的战术失误。

这些不是虚假的 RPG 数值。装备一个天赋会真正修改 Agent 的指令栈。

因此：

> **Prompt 就是构筑。**

---

## 9. 多 Agent / Swarm 方向

MVP 应该从单个 Agent 开始。

一旦单 Agent 循环跑通，就可以扩展成 swarm。

可能的角色：

- **侦察兵（Scout）** — 观察敌人组成与威胁；
- **建造者（Builder）** — 执行防御塔放置与升级；
- **经济（Economy）** — 管理资源策略；
- **指挥官（Commander）** — 协调战略决策；
- **批评者（Critic）** — 检查高风险决策；
- **记忆（Memory）** — 从过往局中检索有用的经验教训。

然后同一个游戏可以比较：

**单 Agent vs Agent Swarm**

在相同的地图、种子、模型预算和约束下。

可能的测量项：

- 到达的波次；
- 决策延迟；
- token；
- 成本；
- 失败动作；
- 通信开销；
- 存活时长；
- 适应质量。

一个核心问题变成：

> **加入更多 Agent 真的能让系统更好吗？**

更多 Agent 可能提升并行度与专业化，但也可能引入延迟、通信开销、冲突和成本。

这种权衡应该呈现在游戏中，而不是藏在日志里。

---

## 10. 更长期的游戏机制

这些是扩展，而非 MVP 要求。

### Prompt vs Prompt

两名人类使用相同的基础模型、地图、种子和预算。

唯一的区别是他们的策略 Prompt。

双方的 AI 独立作战，更好的 Prompt 构筑存活更久。

### Prompt 卡牌

休闲玩家用可理解的卡牌来构建策略，而不是从零写所有内容。

进阶玩家可以编辑原始 Prompt 文本。

### Prompt 继承

死亡之后，AI 提出所获经验教训。

玩家只能为下一代保留有限数量的经验。

这在完整的回合制历史与可复用的经验之间创造出有意义的区分。

### Prompt 演化

成功的 Prompt 可以：

- 分叉；
- 变异；
- 比较；
- 交叉；
- 选择。

Prompt 变得类似于基因组。

### 人类架构师 vs AI 架构师

人类在固定算力预算下设计一支 Agent 团队。

AI 设计另一支。

双方对抗同一个挑战。

### 自带 Agent（Bring Your Own Agent）

未来的一种竞技模式可以允许开发者提交自己的：

- 模型；
- Prompt；
- Agent 拓扑；
- 记忆策略；
- 工具策略。

游戏于是变成一个 Agent 竞技场。

---

## 11. 产品层次

项目可以有三个层次，而不需要三个独立产品。

### 面向普通玩家

**一款有趣的 roguelike 塔防，你通过语言训练一个 AI。**

### 面向 AI 初学者

**一种快速理解 Prompt 如何改变 AI 行为的方式。**

玩家通过即时结果学习，而不是通过教程。

### 面向 Agent 构建者

**一个可复现的环境，用于在实时压力下实验 Agent 架构。**

顺序很重要：

> **游戏 → 发现 → 基准测试**

而不是：

> 基准测试 → 套上游戏外衣的可视化。

---

## 12. 设计原则

### 游戏优先

如果迭代 Prompt、观看 AI 作战这件事本身不好玩，无论基准测试做得多精巧，项目都会失败。

### 结果可观察

每一个重要的 AI 决策都应对战场产生可见影响。

### Prompt 敏感度

不同的合理 Prompt 必须产生有实质差异的行为。

### 实时压力

思考时间必须是有代价的。

### 确定性内核

底层游戏模拟应该是常规、可靠、可复现的。

### 收窄的 Agent 动作空间

Agent 选择策略，并调用少量明确的工具。

### 失败即内容

糟糕的 AI 决策应该是可见的、可理解的，并且对玩家的下一次尝试有用。

### 范围纪律

一款打磨精致、只有一张地图但拥有强大“Prompt → 行为 → 结果”循环的游戏，比一个半成品平台更有价值。

---

## 13. 黑客松范围

目标是：

> **在黑客松期间做出一个真正可玩的版本。**

优先级顺序：

### P0 — 验证机制

- 确定性的塔防模拟；
- LLM 工具调用；
- 策略 Prompt 输入；
- Agent 能自主游玩；
- 两个不同的 Prompt 产生明显不同的行为。

### P1 — 完成游戏循环

- 开始本局；
- 观看 AI 决策；
- 游戏结束；
- 简单的事后复盘；
- 编辑 Prompt；
- 重试；
- 波次计分。

### P2 — 让 AI 变得可读

在不给玩家造成信息过载的前提下展示：

- Agent 正在思考 / 等待；
- 当前决策；
- 动作；
- 延迟；
- 或许还有 token 用量。

### P3 — 一个 swarm 功能

只在上述内容稳定之后再做。

优先做一个简单的**单 Agent vs Swarm**对比，而不是一个大型可配置的多 Agent 平台。

### P4 — 打磨

- 新手引导；
- 视觉清晰度；
- 可靠的演示；
- 兜底行为；
- 适合旁观者观看的呈现方式。

## 14. 工作定位

### 一句话

> **一款 roguelike 塔防，你的 Prompt 就是你的构筑，AI 就是你的玩家。**

### 三行解释

> **Prompt 是构筑。**
> **AI 是玩家。**
> **塔防是世界。**

### 玩法一句话

> **战斗 → 死亡 → 学习 → 重写 Prompt → 再战。**

### 教育一句话

> **通过观察你的文字如何改变它的行为，学会如何与 AI 协作。**

### Agent 工程一句话

> **在游戏之下，每一局都是关于 Agent 延迟、决策质量、成本、适应与协作的实时实验。**

## 15. 北极星

玩家实际上并不是在玩防御塔。

玩家在学习的是：

> **我该如何把意图传达给一个智能体，让它能在没有我的情况下成功行动？**

传统游戏教的是：

**人类 → 直接控制 → 世界**

本作探索的是：

**人类 → 意图 → AI → 决策 → 行动 → 世界**

塔防环境让这种关系变得可见、可玩、可比较、可犯错、可改进。

如果一位玩家改了自己 Prompt 里的一句话，看着 AI 改变行为、活得更久，并立刻想再试一次，那么黑客松版本就成功了。
